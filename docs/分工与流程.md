# 分工与协作流程

> 3 人团队 = 每人一块互不重叠的目录 + 一个集成人（组长）负责顶层。
> 最后更新：2026-11-25

---

## 一、分工表

| 人 | 代码领地（只改这里） | 职责 | 兼任 |
|---|---|---|---|
| **组长（你）** | `top/`、`common/`、`modules/m_disp_oled/`、`modules/m_alarm/`、`modules/m_uart/` | 框架、总连线、主程序（快照+阈值+报警+LED+蜂鸣器）、OLED 与数码管显示、串口上报 | **集成人**：维护 `sys_top.v` 与 XDC、审 PR、合并、打 tag、上板调试 |
| **成员B** | `modules/m_sensor_th/`、`modules/m_sensor_light/` | Pmod HYGRO（I2C 温湿度）、Pmod ALS（SPI 光照）驱动 | 维护传感器仿真模型（I2C 从机模型 / SPI ADC 模型）、写传感器标定说明 |
| **成员C** | `modules/m_disp_vga/` | VGA 640×480 外接显示器仪表盘渲染 | 维护 VGA 上板调试（显示器兼容性、颜色/坐标标定） |

**红线**：除组长外，任何人不得修改 `top/sys_top.v`、`xdc/sys_pins.xdc`、`docs/接口协议.md`。

## 二、分支模型

```
main      ← 可交付版本（每次联调成功、上板验证过才合进来，打 tag v0.1 / v0.2 …）
  └─ develop    ← 集成分支（日常最新代码都汇到这里）
       ├─ feature/sensor_th        （成员B）
       ├─ feature/sensor_light     （成员B）
       ├─ feature/vga              （成员C）
       └─ feature/oled_disp        （组长）
```

### 日常循环（每人每天）

```bash
# 1) 开始干活前，先同步
git checkout develop
git pull origin develop
git checkout feature/xxx      # 已存在就切过去
git merge develop             # 把别人的新代码合进来（每天至少一次）

# 2) 只改自己目录里的文件，边写边提交
git add modules/m_sensor_th/
git commit -m "feat(th): 加 I2C START/STOP 时序"
git push origin feature/xxx

# 3) 单元仿真全过、自己模块综合无错 → 发起 PR
#    feature/xxx → develop，组长 review 后 merge
```

### 提交信息格式（必须）

```
<类型>(<模块>): <一句话说明>

类型：feat 新功能 / fix 修 bug / refactor 重构 / docs 文档 / chore 杂项 / test 仿真
例子：feat(th_sensor): 实现 SHTC3 读温湿度时序并通过 tb_th_sensor
      fix(vga): 修正 hsync 前后沿宽度
```

## 三、每天开工/收工的标准动作

**开工**
1. `git pull`（+ `git merge develop`）；
2. 如果别人新增了 `.v` 文件：在 Vivado Tcl Console 里 `source scripts/create_project.tcl` 重建工程（约 30 秒，只重收文件）；
3. 把自己模块的 tb 设为仿真顶层，先跑一遍确认"昨天没把别人的东西弄坏"。

**收工**
1. 自己模块的 tb 必须 PASS；
2. `commit` + `push` 到自己的 feature 分支（云端备份，电脑坏了不心疼）；
3. 在群里发一句：改了哪些文件、接口有没有动。

## 四、三条硬性约定

1. **时钟复位统一**：只有 100 MHz 一个时钟，内部 `rst` 高有效同步复位；禁止派生时钟、禁止 `negedge rst` 混用。
2. **不碰别人目录**：接口不够用就提，由组长统一改 `sys_top.v` 并更新 `docs/接口协议.md`，两个人同时改顶层必冲突。
3. **小步提交**：写完一个状态机/测通一个功能点就提交，别攒一天再提交（回滚时你会感谢自己）。

---

## 五、PR 检查清单（组长 review 用）

- [ ] 只改了自己目录（`git diff --stat` 确认）
- [ ] 没提交 Vivado 缓存（`work/`、`*.jou`、`*.log` 不应出现在 diff 里）
- [ ] 自己模块的 tb 在 `scripts/sim_iverilog.bat` 里 PASS
- [ ] 端口与 `docs/接口协议.md` 完全一致（位宽、符号、名字）
- [ ] 没有新增第二个时钟（搜 `always @(posedge` 里是不是都是 `clk`）

## 六、常见冲突与处理

| 情况 | 处理 |
|---|---|
| 两个人都改了 `sys_top.v` | 回滚自己的改动，把需求告诉组长，由组长统一改 |
| `create_project.tcl` 报找不到文件 | 新增的 `.v` 没进 git（`git status` 看看），或路径不在 glob 覆盖范围 |
| 合并后 Vivado 报模块重复定义 | 有人把同一个模块在两个人目录里各写了一份 → 只保留一份，另一份删除 |
| 我的 tb 突然 FAIL 了但没改代码 | 先 `git log` 看是不是别人动了自己的模块目录（违反约定） |
