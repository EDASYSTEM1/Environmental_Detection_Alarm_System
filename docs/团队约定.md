# 团队约定（v3 环境监测警报系统，3 人组）

> 这是三个人一起干活时必须共同遵守的规则，写下来是为了**少吵架、少返工**。
> 最后更新：2026-11-25　适用仓库：`v3_env_monitor_framework`（分支 `main` / `develop`）

---

## 〇、一句话版本

**每人只改自己目录；接口按文档冻结；每个模块都要仿真过；每次提交都要能编译。**

---

## 一、目录领地（不许越界）

| 人 | 只能改这些 | 负责内容 |
|---|---|---|
| **组长** | `top/`、`common/`、`modules/m_disp_oled/`、`modules/m_alarm/`、`modules/m_uart/`、`xdc/`、`scripts/`、`docs/` | 框架、顶层、主程序、OLED、报警/蜂鸣器、串口上报 |
| **成员B** | `modules/m_sensor_th/`、`modules/m_sensor_light/` | Pmod HYGRO（I2C 温湿度）、Pmod ALS（SPI 光照） |
| **成员C** | `modules/m_disp_vga/` | VGA 640×480 仪表盘 |

- 改别人目录 = 直接打回，不看内容；
- 需要别人配合，先在群里说，不要自己动手。

---

## 二、接口冻结（最重要的一条）

- 端口**名字、位宽、方向、有无符号**以 `docs/接口协议.md` 为准，那是唯一依据；
- **要改接口** → 群里说明理由 → 组长改 `sys_top.v` + 接口文档（**同一个提交**）→ 其他人 `git pull` 后重跑 `scripts\create_project.tcl`；
- **任何人都不得在自己的分支里改** `top/sys_top.v`、`xdc/sys_pins.xdc`、`docs/接口协议.md`。

> 为什么这么严：三个人同时改顶层，合并冲突会让一整天白干。

---

## 三、时钟与复位（硬件红线，出事最难查）

1. **全系统只有一个时钟**：100 MHz（`CLK100MHZ`）。禁止 `always @(posedge clk_div)` 这种"派生时钟"；
2. 需要"多久做一次"的地方，用 **tick 使能**：`tick_1hz` / `tick_10hz` / `tick_1khz`；
3. 内部复位统一叫 `rst`，**高有效、同步释放**，只能来自 `common/rst_sync.v`；
4. 模块输出**先打一拍寄存器**再给别的模块用，别把长组合逻辑跨模块串起来（时序会崩）。

---

## 四、编码规范

- **一个功能模块一个 `.v` 文件**，文件名 = 模块名（课程明确要求）；
- 状态机用 `localparam` 定义状态名，`case` 必须有 `default`；
- **禁止生成锁存器**：`always @(*)` 里所有分支都要给同一个信号赋值；
- 位宽写清楚，不要依赖隐式扩展/截断；跨模块位宽不一致按 bug 处理；
- 建议文件开头加 `` `default_nettype none ``（拼错信号名立刻报错，而不是偷偷生成一根 1 位线）；
- 注释写**为什么这么做**，不要写"给 a 赋 b"这种废话。

---

## 五、仿真要求（提 PR 的前提）

- 每个模块自带 `sim/tb_xxx.v`，**自检式**（结尾打印 `==== XXX TEST PASSED ====`）；
- 统一用 `scripts\sim_iverilog.bat` 跑（Icarus）；**本机 Vivado 是 BASIC 授权、没 xsim**，别在 Vivado 里点仿真；
- 新增 `.v` 文件要加进 `sim_iverilog.bat` 的 RTL 列表（`create_project.tcl` 是 glob 自动收，不用改）；
- 自己模块的 tb 不 PASS，不许提 PR。

---

## 六、构建与上板

| 操作 | 命令 |
|---|---|
| 建工程 | `scripts\create_project.bat` |
| 综合+实现+出 bit | `scripts\build_bitstream.bat` |
| 下载到板子 | `tools\program_board.bat` |
| 串口自检 | `tools\serial_check.ps1` |

- **本机烧不了 QSPI Flash**，所以断电后程序不保留，每次上电都要重新下载（约 40 秒）；
- `bitstream/top.bit` 入库（别人可以直接下载），`top.bin` 不入库；
- 改过 `xdc` 之后必须由组长跑一次全量构建并确认 WNS > 0。

---

## 七、Git 规范

- 分支：`feature/sensor_th`、`feature/sensor_light`、`feature/vga`、`feature/oled_disp`；
- 流程：`feature/xxx` → PR → `develop` → 联调通过后由组长合到 `main` 并打 tag；
- 提交信息：`feat(模块): 说明` / `fix(模块): 说明` / `docs: 说明`；
- **只提交自己目录 + 必要文档**；绝不提交 `work/`、`*.jou`、`*.log`、`*.bin`；
- 每天至少 push 一次（云端备份，电脑坏了不心疼）。

---

## 八、每天的标准动作

**开工**
1. `git checkout develop && git pull && git merge develop`（在自己分支里）；
2. 跑一次 `scripts\sim_iverilog.bat`，确认没被别人弄坏；
3. 再动代码。

**收工**
1. 自己模块 tb PASS；
2. `commit` + `push` 到自己的 feature 分支；
3. 群里发一句：改了哪些文件、接口有没有动。

---

## 九、课程验收相关

- 每个功能模块单独 `.v` + 单独仿真（动员 PPT 第 5 页的硬性要求）；
- 最终要**脱机演示**：本机 Flash 烧不进去，录屏时用电脑下载 bit，并说明断电后需重下；
- 报告里必须写**分工 + 贡献度百分比**（PPT 第 20 页要求）；
- 录屏/答辩前，统一用 `develop` 分支的 bit，别各拿各的。

---

## 十、三条最容易犯的错（贴墙上）

1. **信号名拼错** → Verilog 偷偷生成 1 位 wire，编译能过、功能全错（加 `` `default_nettype none `` 可防）；
2. **用分频器当时钟** → 时序分析不覆盖，仿真好的设计上板偶发死机；
3. **私改 `sys_top.v`** → 三人合并必冲突，一整天白干。
