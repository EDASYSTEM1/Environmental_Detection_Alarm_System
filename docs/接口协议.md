## 〇、全局约定（必须遵守）

| 项目 | 约定 | 原因 |
|---|---|---|
| 时钟 | 全系统**只有一个** 100 MHz `clk`（E3） | 多时钟 = 跨时钟域 = 三个人互相甩锅 |
| 时钟衍生 | **禁止**用分频器输出当时钟（不写 `always @(posedge clk_div)`） | 派生时钟会被 Vivado 报 clock 警告，时序分析不覆盖 |
| 节奏控制 | 用 `tick_xxx`（单周期使能脉冲）控制"多久做一次" | 单时钟域内最安全的做法 |
| 复位 | 内部 `rst` **高有效**，由 `rst_sync` 从 `~CPU_RESETN` 异步置位、同步释放 | 统一极性，避免"A 高有效、B 低有效" |
| 复位用法 | `if (rst) ... else ...` 同步复位写法 | 全组同一模板 |
| 数值格式 | 定点整数，缩放写死在端口名里（见第二节） | 避免三个人对"单位"理解不一致 |
| 数据更新 | 每 1 Hz 一次，配 `*_valid` 单周期脉冲 | 低速传感器不需要握手 |
| 模块命名 | `snake_case`，文件名 = 模块名 | 便于 `create_project.tcl` 用 glob 自动收文件 |
| 端口命名 | `方向_含义`：`din_` / `dout_` / `o_` / `i_` 可选，但同一模块内风格统一 | 可读性 |

**禁止事项**：跨模块用 `wire` 直接互相读内部信号（`u_b.internal_x`）。只能走端口。

### 0.1 电平极性速查（最容易记混，一定看这张表）

| 信号 | 极性 | 说明 |
|---|---|---|
| 板载复位键 `CPU_RESETN` | **低有效**（按下 = 0） | 硬件决定，改不了 |
| 内部 `rst` | **高有效**（按下后 = 1） | 全组统一约定，由 `common/rst_sync.v` 从 `~CPU_RESETN` 转换 |
| 按键 `BTN[4:0]` | **高有效**（按下 = 1） | ⚠️ 和复位键**相反**，不要套用 |
| 拨码开关 `SW[15:0]` | 1 = 拨上 | |
| `LED[15:0]` | 1 = 亮 | |
| 数码管段选 `SEG` / 位选 `AN` | **低有效** | 共阳极：0 = 点亮 / 选中 |
| OLED `CS` / `RES` | **低有效** | 0 = 选中 / 复位 |
| OLED `D/C` | 1 = 数据，0 = 命令 | |
| ALS `~CS` | **低有效** | 0 = 选中 |
| UART `tx` | 空闲高 | 起始位 = 0，停止位 = 1 |

三条规则：

1. **模块内部一律 `if (rst) ... else ...`**（高有效），不要写 `if (!rst)`；
2. 不要自己反转极性——需要反相就在端口处例化一级并写注释，否则三个月后没人看得懂；
3. 新增任何"低有效"信号（如新外设的片选），必须在本表补一行。

## 二、数据格式（缩放约定，最容易出错的地方）

| 信号 | 类型 | 单位 | 例子 | 说明 |
|---|---|---|---|---|
| `temp_x10` | `signed [15:0]` | 0.1 ℃ | `253` = 25.3 ℃，`-52` = −5.2 ℃ | **有符号**，冬天室外可能为负 |
| `humi_x10` | `[15:0]` | 0.1 %RH | `550` = 55.0 %RH，范围 0~1000 | 无符号 |
| `lux` | `[15:0]` | 1 lux | `320` = 320 lux | 无符号，B 负责把 ADC 原始值换算成 lux |
| `adc_raw` | `[11:0]` | 原始码值 | 0~255（8 位） | ALS 板载 **ADC081S021 是 8 位**，只有低 8 位有效、高 4 位恒 0；端口留 12 位是为了以后换 12 位模块不用改接口 |
| `*_status` | `[7:0]` | 位标志 | 见第三节 | 0 = 正常 |

**为什么不用 BCD**：BCD 是"显示格式"，属于我（显示）的活。传感器和报警只输出二进制定点数，
这样 B 不用关心数码管怎么画，我改显示也不用动 B 的代码。

## 三、状态字 `status[7:0]` 定义（统一）

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | `ST_VALID` | 至少成功读到过一帧数据 |
| 1 | `ST_NACK` | I2C 从机无应答 / SPI 无响应 |
| 2 | `ST_TIMEOUT` | 通信超时（超过约定时钟数没有回数据） |
| 3 | `ST_BUSY` | 上电初始化未完成（前 100 ms 会有） |
| 7:4 | 保留 | 各模块自定义调试位，**不要**给报警模块用 |

**单模块正常判定（v1.3 统一，唯一标准）**：`module_ok = (status[3:0] == 4'b0001)`，即"拿到过有效数据 + 无 NACK + 无超时 + 初始化完成"。

> ⚠️ 早期版本写"`status == 0` 表示正常"，那种写法分不清"还没读到"和"读到了"，已废弃。
> 代码已同步：`sensor_snapshot` 用 `th_status[3:0] == 4'b0001` 判正常，传感器空壳输出 `8'h01`。

快照模块把两路状态汇总成：

```
sensor_status[0] = th_ok      // 温湿度正常
sensor_status[1] = ls_ok      // 光照正常
sensor_status[2] = th_stale   // 连续 3 个采样周期没拿到数据
sensor_status[3] = ls_stale
```

## 四、五个模块的冻结端口

### 4.1 `th_sensor`（成员B：Pmod HYGRO，I2C）

```verilog
module th_sensor (
    input  wire               clk,
    input  wire               rst,
    input  wire               sample_tick,   // 1 Hz 单周期脉冲：该采样了
    output wire               scl,           // I2C SCL（100 kHz，由 100 MHz 分频）
    inout  wire               sda,           // I2C SDA（开漏，模块自带上拉，必须 inout）
    output reg  signed [15:0] temp_x10,
    output reg         [15:0] humi_x10,
    output reg         [7:0]  status,
    output reg                valid          // 采完一帧的 1 拍脉冲
);
```

**接口语义**：`sample_tick` 来了开始一次"读温湿度"事务；事务结束那拍 `valid` 拉高 1 拍，
同时更新 `temp_x10/humi_x10`。没拿到数据时**不要**更新数值，只置 `status[1]`。

**硬件连接（已按官方手册核对）**：Pmod HYGRO 是 **6 针**模块，`1=NC 2=NC 3=SCL 4=SDA 5=GND 6=VCC`，
插 JB 口（上排 1~6 脚）→ SCL = JB[3] = G16，SDA = JB[4] = H14。板载传感器是 **TI HDC1080**（I2C 7 位地址 **0x40**，写 0x80 / 读 0x81）。

**HDC1080 驱动流程（B 组员按这个写）**：

1. 上电等 ≥15 ms；向配置寄存器 `0x02` 写 `0x1000`（14 位分辨率、温湿度连续测量）；
2. 每个 `sample_tick`：向 `0x40` 写 1 字节寄存器指针 `0x00` → 发 STOP，**触发一次转换**；
3. 用计数器延时 **20 ms**（14 位温+湿约 13 ms，留余量）；
4. 向 `0x40` 读 4 字节：`T_MSB, T_LSB, H_MSB, H_LSB`（最后一字节主机回 NACK + STOP）；
5. 换算（无除法，只用移位）：
   - `temp_x10 = (raw_T * 1650) >> 16 - 400`（单位 0.1 ℃，-40~125 ℃）
   - `humi_x10 = (raw_H * 1000) >> 16`，超过 1000 钳到 1000

### 4.2 `light_sensor`（成员B：Pmod ALS，SPI）

```verilog
module light_sensor (
    input  wire        clk,
    input  wire        rst,
    input  wire        sample_tick,
    output wire        als_cs,      // 低有效片选
    output wire        als_sclk,    // SPI 时钟（建议 1 MHz 以下）
    input  wire        als_miso,    // ADC 数据，MSB 先出
    output reg  [11:0] adc_raw,
    output reg  [15:0] lux,
    output reg  [7:0]  status,
    output reg         valid
);
```

**接口语义**：同 4.1。`lux` 是由 `adc_raw` 按曲线换算出的照度（换算表写在自己模块里，
并在自己 README 里写清楚，方便报告画图）。

**硬件连接（已按官方手册核对）**：Pmod ALS 是 **6 针**模块，`1=~CS 2=NC 3=MISO 4=SCLK 5=GND 6=VCC`，
插 JC 口 → CS = JC[1] = K1，MISO = JC[3] = J2，SCLK = JC[4] = G6。
板载 ADC 是 **ADC081S021（8 位）**：CS 拉低后给 16 个 SCLK，数据帧为 **3 位前导 0 + 8 位有效数据（MSB 先出）+ 5 位尾随 0**，SCLK 上限 4 MHz（建议 1 MHz）。

> ⚠️ **不能直接取低 8 位**：有效数据在 16 位移位寄存器的中间位置，正确取法是 `shift_reg[11:4]`（若在上升沿采样、且从第 1 个时钟就开始移位，则可能是 `[12:5]`）。B 组员请在 tb 里放一个 ADC 行为模型（按"3 个 0 + 8 位 + 尾随 0"输出已知码值），仿真能取对再上板。

所以 `adc_raw[11:0]` 高 4 位恒填 `4'b0000`、低 8 位填有效码值（端口保持 12 位，以后换 12 位 ADC 不用改接口）。

### 4.3 `alarm_ctrl`（组长：阈值判定 + 人机交互）

```verilog
module alarm_ctrl #(
    parameter integer CLK_HZ        = 100_000_000,
    parameter integer ACTIVE_BUZZER = 0        // 0 = 无源蜂鸣器(方波) / 1 = 有源(电平)
) (
    input  wire               clk,
    input  wire               rst,
    input  wire               sample_tick,
    input  wire signed [15:0] temp_x10,
    input  wire        [15:0] humi_x10,
    input  wire        [15:0] lux,
    input  wire        [7:0]  sensor_status,   // 快照汇总（第三节）
    input  wire        [15:0] sw,
    input  wire        [4:0]  btn,             // 已消抖
    output reg  [3:0]  alarm_level,            // 0 正常 / 1 注意 / 2 警告 / 3 严重
    output reg  [3:0]  alarm_src,              // bit0 温度 / bit1 湿度 / bit2 光照 / bit3 传感器故障
    output reg  [15:0] led,
    output wire               buzz             // 到 Pmod JD 第 1 脚（自制蜂鸣器模块）
);
```

**蜂鸣器说明（自制 Pmod 模块，插 JD 口）**：

- `alarm_ctrl` 内部例化了 `buzz_drv`，由它负责产生 2 kHz 方波（无源）或电平（有源）；
- **无源蜂鸣器**：`ACTIVE_BUZZER = 0`（默认），给方波才响；
- **有源蜂鸣器**：把 `top/sys_top.v` 里 `alarm_ctrl #(.ACTIVE_BUZZER(0))` 改成 `1`，给高电平就响；
- 上板试一次就知道是哪种：默认配置不响 → 改成 1 再试；
- 门控：`SW[10]=1` 允许响、`SW[11]=1` 静音，等级 ≥2 才响。

### 4.6 `report_tx`（组长：串口上报，给上位机 / 串口助手）

```verilog
module report_tx #(
    parameter integer CLK_HZ = 100_000_000,
    parameter integer BAUD   = 115200
) (
    input  wire               clk,
    input  wire               rst,
    input  wire               report_tick,     // 100 ms 上报节拍
    input  wire signed [15:0] temp_x10,
    input  wire        [15:0] humi_x10,
    input  wire        [15:0] lux,
    input  wire        [3:0]  alarm_level,
    input  wire        [7:0]  sensor_status,
    output wire               uart_txd         // 板载 USB-UART，FPGA 引脚 D4
);
```

**帧格式（固定 37 字节，115200 8N1，每 100 ms 一行）**：

```
$ENV,T=+25.3,H=55.0,L=0320,A=2,S=03\r\n
     │ │      │      │       │    └ 传感器状态字（16 进制，00 = 正常）
     │ │      │      │       └────── 报警等级 0~3
     │ │      │      └────────────── 光照，4 位左补 0
     │ │      └───────────────────── 湿度 %RH，1 位小数
     │ └──────────────────────────── 温度 ℃，1 位小数，带 +/- 符号
     └────────────────────────────── 帧头
```

- **定长 + 左补 0**：上位机按逗号切分即可，不用猜长度；Verilog 里每个字节对应固定下标，用 `case` 发；
- 数值钳位：温度 ±99.9 ℃、湿度 99.9 %RH、光照 4095 lux 封顶，超了也不会把帧冲乱；
- 发送耗时约 3.2 ms ≪ 100 ms，不会丢帧；
- 电脑端识别：设备管理器里找 `COMx`（FTDI 通道 B），串口助手设 **115200 / 8 / 无校验 / 1 停止位**；
  板子和 JTAG 共用同一根 USB 线，不用额外接线；
- 现成的 PC 端脚本：`tools/pc_monitor.py`（需要 `pip install pyserial`）。

## 五、开关 / 按键 / LED 分配

### 5.1 拨码开关 `sw[15:0]`（阈值设定，报警模块用）

| 开关 | 含义 | 计算 |
|---|---|---|
| `SW[3:0]` | 温度上限 | `20 + n×2` ℃，即 20/22/…/50 ℃ |
| `SW[7:4]` | 湿度上限 | `40 + n×5` %RH，即 40/45/…/115 %RH |
| `SW[9:8]` | 光照下限（太暗报警） | `20 / 40 / 80 / 160` lux |
| `SW[10]` | 蜂鸣器使能 | 1 = 允许响 |
| `SW[11]` | 静音 | 1 = 强制不响（演示用） |
| `SW[12]` | 自检模式 | 预留（假数据演示） |
| `SW[15:13]` | 保留 / VGA 拓展 | 可由成员C 用于切换 VGA 视图（总览 / 折线图）或颜色主题，需在自己模块 README 写明 |

> 注意：`SW[8]`、`SW[9]` 在 1.8 V bank，XDC 里必须是 `LVCMOS18`，别改。

### 5.2 按键 `btn[4:0]`（已过 10 ms 消抖）

| 位 | 板载键 | 引脚 | 建议用途 |
|---|---|---|---|

| `btn[1]` | BTNU | M18 | 切换显示页 |
| `btn[2]` | BTND | P18 | — |
| `btn[3]` | BTNL | P17 | — |

### 5.3 LED `led[15:0]`

| 位 | 含义 |
|---|---|
| `LED[3:0]` | `alarm_level`（0~3） |
| `LED[7:4]` | `alarm_src`（温度/湿度/光照/故障） |

## 六、显示内容规范（OLED 与 VGA 必须一致）

屏幕布局统一成 **4 行 × 16 字符**（OLED 128×32 正好 16×4 个 8×8 字；VGA 按同样文字内容放大画）：

```
第 1 行:  ENV MONITOR
第 2 行:  T:+25.3C H:55.0%
第 3 行:  L:0320lx ALM:2
第 4 行:  OK / ALARM! / SENSOR FAIL
```

- 每行**定宽 16 字符**，不足补空格（与 OLED 的 16 字符/行严格对应）；
- 温度**永远带符号**（`+`/`-`），保证第 2 行宽度固定：`T:+25.3C` / `T:-05.2C`；
- 湿度一位小数；光照 4 位数字左补 0（`0320lx`）；
- 报警等级显示成 `ALM:0..3`；
- 第 4 行状态优先级：传感器故障 → `SENSOR FAIL`，否则等级 ≥2 → `ALARM!`，否则 `OK`；
- 两边字形都用 `common/font_rom.v`（33 个字符的 8×8 点阵，由 `tools/gen_font.py` 生成），
  保证 OLED 和 VGA 的字形一致。

## 七、端口变更流程（唯一合法路径）

1. 在群里说明"要加/改哪个模块的哪个端口，为什么"；
2. 组长确认后改 `top/sys_top.v` + 本文件，**同一次提交**里完成；
3. 另外两人 `git pull` 后重新跑一次 `source scripts/create_project.tcl`（新增文件要重新收）；
4. 任何人不得在自己分支里私改 `sys_top.v`。

## 附录 B：PR 门禁与 .gitignore 规范

**PR 合并到 `develop` 前必须自检**：

1. 自己模块的 tb 全 PASS（`scripts\sim_iverilog.bat`），PR 里贴运行结果；
2. 本地跑过综合，无 Error、无 latch、无多驱动警告；
3. `git status` 干净，**不得包含** `work/`、`.Xil/`、`*.jou`、`*.log`、`*.dcp`；
4. 只动自己目录（组长除外）。

**`.gitignore` 原则**：

- 由组长维护，组员不得擅自删改规则；
- 本地 Vivado 工程（`work/`）、日志、IP 中间产物一律忽略；
- 若引入 IP 核，只提交 `ip/<name>/<name>.xci`；
- 例外：`bitstream/top.bit` 允许入库（方便组员直接下载），但不允许 `git add -f` 强推其它二进制。
